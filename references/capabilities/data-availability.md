# Data and Code Availability

## Use for

Data Availability, Code Availability, repository plans, accession numbers, dataset citations, restricted data, source data, supplementary datasets, and FAIR checks.

## Inventory

Identify:

- raw data;
- processed data;
- analysis code;
- trained models and configuration;
- source data behind figures;
- questionnaires, protocols, and metadata;
- third-party data;
- sensitive or restricted material.

## Access route

For each item choose:

- open repository;
- controlled-access repository;
- domain repository;
- institutional repository;
- supplementary information;
- justified request-based access;
- not shareable with a specific legal, ethical, or licence reason.

Do not use “available on reasonable request” as a default convenience.

## Repository and identifier

Prefer a stable, field-appropriate repository with versioning and a persistent identifier. Record DOI or accession only after it exists. Cite datasets as research outputs.

## Statement

State:

- what is available;
- where;
- identifier or stable link;
- access conditions;
- third-party restrictions;
- timing or embargo;
- source-data coverage;
- code environment and licence where relevant.

## FAIR check

Check findability, access, interoperability, reuse, README, data dictionary, provenance, version, licence, file organization, and machine-readable metadata.

## Sensitive data

For patient, personal, Indigenous, confidential, commercial, or security-sensitive data, follow ethics approval, consent, law, and institutional policy. Never promise release that conflicts with those constraints.
