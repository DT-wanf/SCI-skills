# Stage Diagnosis

## Rule

The actual stage is the earliest essential stage that has not met its acceptance criteria. A manuscript draft, code repository, or partial result does not automatically validate preceding stages.

## Procedure

1. Record the user's self-reported stage.
2. Review available artifacts against each earlier stage's outputs and acceptance criteria.
3. Mark each stage `passed`, `partially_passed`, `failed`, or `not_assessed`.
4. Select the earliest critical non-passed stage.
5. Preserve usable downstream materials as provisional assets; do not discard them.
6. Explain the diagnosis in Chinese and name the specific missing evidence.

## Confidence

- High: direct artifacts support the assessment.
- Medium: sufficient description but incomplete files.
- Low: user description is too sparse or contradictory.

## Skip handling

If the user requests downstream writing before upstream validation, provide provisional assistance, label upstream dependencies, and keep stage status unchanged.
